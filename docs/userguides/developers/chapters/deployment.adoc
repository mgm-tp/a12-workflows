=== Clustering

==== CIB 7 Process Engine

CIB 7 allows clustering by distributing the process engine across multiple nodes which access a shared database.

image::assets/images/deployment-clustering-cib7-overview.png[Architecture sketch of clustered CIB 7]

NOTE: For details, please refer to the link:https://camunda.com/platform-7/performance/[Camunda documentation on performance and scalability,role=external], in particular the section titled "Clustering".

==== CIB 7 Job Executor

In CIB 7, the _Job Executor_ is responsible for executing any _asynchronous continuations_ which are triggered during process execution. Asynchronous continuations can be triggered e.g. by transaction boundaries or timer events.

NOTE: For details about the Job Executor, please refer to link:https://docs.cibseven.org/manual/{cibsevenVersion}/user-guide/process-engine/the-job-executor/[CIB 7's official documentation.,role=external]

CIB 7 differentiates between _homogenous_ and _heterogeneous_ deployments. _Homogenous_ means that the same process applications are deployed on all nodes.

NOTE: For details about these variants, please refer to link:https://docs.cibseven.org/manual/{cibsevenVersion}/user-guide/process-engine/the-job-executor/#cluster-setups[cluster setups for the Job Executor.,role=external]

In short, in case of heterogeneous cluster, you must set the following Spring config:

[source,properties]
----
camunda.bpm.generic-properties.properties.jobExecutorDeploymentAware=true
----

NOTE: The above configuration is equal to setting `<property name="jobExecutorDeploymentAware">true</property>` in XML as shown in the Camunda documentation.

== Monitoring

Both CIB 7 and the Workflows Extension (Data Services) provide Micrometer for monitoring.

NOTE: CIB 7 provides additional monitoring capabilities, see link:https://docs.camunda.io/docs/components/best-practices/operations/operating-camunda-c7/#monitoring-performance-indicators[Camunda monitoring documentation].

== Recovery

When crashed or restarted, CIB 7 will automatically continue execution from the last state ("savepoint") committed to the database.

Savepoints include wait states such as user tasks or timer events. Additionally, savepoints can be modeled in BPMN via _asynchronous continuations_.

NOTE: For details, please refer to link:https://docs.cibseven.org/manual/{cibsevenVersion}/user-guide/process-engine/transactions-in-processes/[transactions in CIB 7,role=external].
