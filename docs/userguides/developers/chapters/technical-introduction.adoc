= How It Works

[NOTE]
====
For modeling related information, please refer to our link:/docs/workflows/ba-docs/index.html[Workflow Modeling Documentation].
====

image::assets/images/architecture-overview.png[Architecture,align="center"]

<<architecture,Architecture>> in the Introduction describes the three parts and where their operations live;
<<anchor-cbr-artifacts,Artifacts>> lists the artifacts with their coordinates and the operations they register.

*As examples, consider the following use cases:*

== Start Process

. The client sends a `START_PROCESS` JSON-RPC request to Data Services.
. Our extension handles this request.
. For this operation, no document changes are to be done.
. The start process request is forwarded to CIB 7 and thus starting a new process of an existing process model.

== Assign Task

. The client sends an `ASSIGN_TASK` JSON-RPC request to Data Services.
. Our extension handles this request.
. The assignee field in our metadata on the document is updated
. The assign request is forwarded to CIB 7.
. CIB 7 sets the assignee as well.

== Loading a Task List

. The client sends a `LIST_DOCUMENTS` JSON-RPC request to Data Services.
.. Under the hood, we add a filter to the query so that only documents currently referenced by a user task are returned
. Data Services handles this request as per usual.

See also our <<anchor-cbr-workflows-extension, list of workflows-specific operations>>.

[[anchor-benefits]]
= Benefits

* Loose coupling between CIB 7 and Data Services:
** CIB 7 knows nothing about models or documents (except that it expects Workflows metadata).
** No need to deploy Document Models to CIB 7.
* CIB 7 does not store documents, only Document References:
** No data duplication.
** Simpler data migration.
* Data Services has access to relevant process metadata (everything in link:/docs/workflows/ba-docs/index.html#anchor-metadata-include[`WorkflowsMetadata_DM.json`]):
** Metadata is available in authorization rules.
** Metadata is available in events and extension points which provide the document.
* Support for external attachments and relationships.

[[anchor-cbr-limitations]]
= Current Limitations

* No eventual consistency guarantees yet for communication between CIB 7 and Data Services.
* Document Models used for workflows *still need metadata as include for now* and must be exactly named *A12WF*:
** A document can only be referenced by a single _User Task_ at a time (because metadata is populated directly in the document).
** Thus, parallel _User Tasks_ _cannot_ reference the same document.
* CIB 7 must be protected in production because it does not integrate UAA authorization.
